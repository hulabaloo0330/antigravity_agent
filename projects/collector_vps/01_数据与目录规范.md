# 线虫行为数据采集规范 v1.0

适用目标：用线虫过去的实测行为预测未来行为。VPS为Linux、Python 3，任务总上限2核CPU、2 GB内存、20 GB存储。DeepSeek-Flash通过远程API调用；VPS不部署本地大模型。

这是设计与交接包，含可执行数据库结构、配置及部署模板，**不是已实现或已部署的联网采集器**。执行器须按02号文档实现并通过验收，再启用定时任务。

## 1. 最重要的约定

一篇论文一个目录，用于查看和追溯；一个数据集可以关联多篇论文，一个论文也可以有多个数据集。不要把论文URL直接变成唯一文件名，不要把每篇论文当成一个独立动物队列。

**SQLite记录唯一正式状态；CSV是程序导出的只读清单。** Agent不直接改CSV、SQL或数值数组。程序创建ID、目录、下载文件、数值统计和状态转换。多个下载任务不共同追加一个CSV。

## 2. 目录布局

```text
/opt/worm-collector/
├── app/                              # 固定的采集程序和受支持解析器
├── .venv/                            # 固定依赖；也计入20 GB
├── config/
│   ├── policy.json                   # 资源上限；模型不可提高
│   └── seeds.json                    # 已知论文和作者数据入口
├── state/
│   ├── catalog.sqlite               # 唯一正式状态库
│   ├── tick.lock
│   ├── scheduler.json               # enabled、间隔、下次到期，由受控工具改写
│   └── discovery_cursor.json        # 检索式、时间区间、页游标及完成状态
├── papers/
│   └── p000001/
│       ├── paper.json               # DOI、PMID、标题、来源及筛选依据
│       ├── evidence/                # 数据可用性说明/README的带来源快照
│       └── current.json             # 指向最近一次完成发布的清单快照
├── objects/sha256/
│   └── ab/<完整SHA256>              # 原下载文件，只读；相同字节只存一份
├── datasets/
│   └── d000001/
│       ├── dataset.json             # 仓库、确切版本、条件和文件引用
│       └── records/
│           └── r000001/
│               └── v000001/         # 一次解析版本，不覆盖旧版
│                   ├── metadata.json
│                   ├── channels.json
│                   ├── behavior.csv.gz
│                   └── qc.json
├── exports/
│   ├── current.json                 # 一次完整导出的快照路径
│   └── snapshot_20260915T080000Z/
│       ├── papers.csv
│       ├── datasets.csv
│       ├── files.csv
│       ├── recordings.csv
│       ├── channels.csv
│       ├── jobs.csv
│       └── by_paper/p000001/
│           ├── datasets.csv
│           ├── files.csv
│           └── recordings.csv
├── incoming/                        # jobID+lease令牌.part；未完成下载
├── tmp/                             # 有容量预留的解析临时文件
├── review/                          # 待核查问题及对象引用，不复制大型原文件
└── logs/                            # JSONL事件日志，按大小轮转
```

数据库主键是程序生成的整数，目录显示为p/d/r加六位数字；超过六位可自然扩展。ID一经分配不因论文改名、更换链接、补充DOI而变更。

DOI规范化后去重；PMID/PMCID和原始链接作为附加标识。标题相似只能触发待核查，不能自动合并。发现DOI和PMID分别命中不同记录时，由程序标记冲突。数据版本使用仓库版本号、Git提交或有日期的实际抓取快照，禁止只写latest。

raw文件通过files表中的object_relpath找到。两篇论文使用同一份数据时，关联到同一dataset或同一sha256对象，避免复制。镜像和原站下载出相同字节，也只保存一个对象。清单需同时保留来源、原始文件名和版本，不能因去重丢掉引用关系。

## 3. 标准化的六张查看表

底层SQL另外有三张关联表，用于论文↔数据集、数据集↔文件、记录↔来源。模型不需要操作它们。以下CSV都由数据库导出：

| 清单 | 一行代表什么 | 关键字段 | 禁止的混淆 |
|---|---|---|---|
| papers.csv | 一篇论文 | paper_id、doi、pmid、title、year、landing_url、screening_state、evidence | 找到论文≠取得数据 |
| datasets.csv | 一个数据集的一个版本 | dataset_id、source_key、repository、version、landing_url、decision、license、declared_record_count、observed_record_count | 论文声称数量≠本次实读数量 |
| files.csv | 一个来源中的一个文件版本 | file_id、source_key、original_name、role、download_url、sha256、bytes、object_relpath、file_state | HTML登录页/PDF/代码文件≠行为数据 |
| recordings.csv | 一段可追溯的动物/实验记录 | recording_id、dataset_id、animal_id_source、split_group_id、representation_key、timing_kind、n_rows、n_channels、qc_state、parsed_relpath | recording_id≠已确认worm_id |
| channels.csv | 一条记录的一列行为量 | recording_id、column_index、column_name、source_name、quantity、source_unit、stored_unit、basis_id、unit_status、evidence | 相同列数≠相同物理含义 |
| jobs.csv | 一次有明确目标的工作 | job_id、action、target_id、status、attempts、next_run_at、lease、error_code | 正在执行≠成功 |

字段完整定义在schema.sql。只有工具计算的数量可以进入observed字段；从文章抽取的数量进入declared字段。时间统一用UTC ISO-8601，例如`2026-09-15T08:00:00Z`，空值使用SQL NULL/JSON null/CSV空单元格。布尔CSV用0或1；UTF-8编码、逗号分隔、标准双引号转义，由CSV库生成。

## 4. 一段行为记录如何存

每条记录一个压缩CSV，采用宽表；一行一个采样点，同一行的行为值必须已对齐。c0001等列的实际含义由channels.json给出，模型无需理解或翻译列名。

```csv
frame_index,time_s,c0001,c0002,c0003,c0004
0,0.000,0.12,0.20,0.03,2.1
1,0.600,0.10,,0.02,2.3
```

上面数字只是格式演示，不是真实实验值。第二行c0002缺失；绝不能自动填成0。加载器把空值转NaN，并生成`valid = isfinite(values)`；该掩码只表示数值存在，不表示追踪质量合格。

若没有核实时间，time_s整列为空，timing_kind=frame_only，只保留frame_index；不能借用其他文件的采样率。若时间与行为长度不同，timing_kind=unaligned，qc_state=review，不输出伪对齐表。明确的采样率允许程序重建秒时间轴，但必须保留原始证据。

channels.json示例：

```json
{
  "recording_id": 1,
  "representation_key": "kinematics:www-export:v1:mm_s-rad-rad_s-pumps_s",
  "channels": [
    {"column_name":"c0001","quantity":"velocity","stored_unit":"mm/s","unit_status":"documented"},
    {"column_name":"c0002","quantity":"head_angle","stored_unit":"rad","unit_status":"documented"},
    {"column_name":"c0003","quantity":"angular_velocity","stored_unit":"rad/s","unit_status":"documented"},
    {"column_name":"c0004","quantity":"pharyngeal_pumping","stored_unit":"pumps/s","unit_status":"documented"}
  ]
}
```

标准字段约定：

| 信息 | 保存方式 |
|---|---|
| 神经活动 | 混合文件允许保留在原对象中；首版行为CSV不加入神经通道 |
| 5维eigenworm系数 | 保存系数、作者基底文件的哈希/版本，保留原尺度 |
| 10维身体通道 | 保存原列序和原单位；文档冲突用unit_status=conflict |
| strain/stage/sex/food/stimulus/gait | 保存来源原文和规范值；未知留空，不能默认N2或成虫 |
| animal_id_source | 有作者明确标识才填；否则留空，用recording_id追踪 |
| split_group_id | 优先原动物，其次会话/视频；同组不能跨训练与测试。只有记录ID时，不能保证跨动物独立性 |
| 缺失、全常数、时间间隔异常 | qc.json保存统计和区间，不让agent解释成生物学结论 |
| 时间/数值单位转换 | 记录公式、依据、转换脚本版本；首版默认保留源单位 |
| 同内容重复 | 原文件按SHA256；解析记录按包含列定义、数值、相对时间和缺失掩码的规范哈希；不同裁剪范围只标疑似重叠 |

4维、5维、10维数据分别属于不同representation_key，**不能直接凑成19维**。不同研究的PCA/eigenworm坐标基底也不能因为都叫a1而直接混用。

QC最少报告：数组长度是否一致、时间是否递增、时间单位证据、各列缺失比例/常数情况、时间断档、重复关系、字段冲突、连续有效区间。对于已解析文件，QC字段不允许用空泛的“正常”代替数值。

## 5. 纳入范围

优先级1：明确实测行为序列，有处理后数据，能识别记录边界和时间顺序。包括速度/转向/进食相关运动、身体姿态、位置序列；允许混有神经活动。

优先级2：实测姿态序列和记录边界明确，但采样率未知。可以按帧预测，标记frame_only；不因此丢弃。

只存元数据：仅原视频、只有申请入口、单文件超过512 MiB、暂时没有下载入口、过大数据包。记录原因，不当作采集成功，也不反复下载。

明确排除：物种不符，或只有平均值/统计图、模拟轨迹、连接组、单纯神经序列且无行为时间序列。摘要缺少说明时给review，不能推断没有数据。

幼虫、突变体、刺激、感染、游泳、爬行都可收集，分别保留条件。连接组、膜电位或钙信号本身不满足本次“行为预测行为”的目标。

## 6. 用上一批数据做规则检查

| 已实际遇到的情况 | 执行规则 |
|---|---|
| Dag一条记录1,600个时间戳，但行为只有1,137个值 | review；保留原数组，不裁到相同长度装作对齐 |
| Ahamed部分序列无已核实采样率 | frame_only，不能照抄crawl的16 Hz |
| Hassinan有28个重复TXT | 相同记录只计一次，保留来源别名 |
| Hassinan混有14、60、约7.5 Hz记录 | 按每条实际时间轴，不使用论文笼统频率覆盖全部文件 |
| Hassinan单位说明与读取代码不一致 | source_scale/conflict，不擅自解释成弧度 |
| 两篇出现同名记录2022-04-05-01，实际信号不同 | 记录ID必须带dataset范围；不能仅凭相同名字合并 |
| 一个pumping通道全0 | 标constant，不自动判定所有时间都不进食 |
| 跨文件存在十几分钟时间断档 | 训练片段断开，不能当相邻帧 |

## 7. 每日报告只看这些

新增论文数、关联数据集数、校验通过文件数、去重后的实际字节数、解析成功记录数、有缺失记录数、frame_only记录数、待核查问题、永久失败数、今日传输量、模型调用数、磁盘剩余额度。

“成功”必须按阶段区分。报告只能从数据库与实际文件核对结果生成，模型不手算总量。日报作为本地文件保存；发送到任何人或群组需另行配置授权渠道。
